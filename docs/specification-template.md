# Plain-task specification template

Use this template in the issue body after refinement.

```md
## Goal
One sentence describing what will change.

## Why
The user or project value.

## Scope
Included files, behaviour, and explicit non-goals.

## Constraints
Technology, style, security, compatibility, or time constraints.

## Acceptance criteria
- [ ] Observable criterion 1
- [ ] Observable criterion 2
- [ ] Tests or a repeatable manual verification step are stated.

## Open questions
- Questions that must be answered before implementation. Write `None` only when genuinely complete.
```

The fixed headings keep implementation prompts comparable and make acceptance criteria reviewable in the pull request.
